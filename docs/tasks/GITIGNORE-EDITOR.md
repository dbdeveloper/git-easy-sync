# GITIGNORE-EDITOR — редактор кореневого `.gitignore`

> Статус: **РЕАЛІЗОВАНО 2026-10-08** (TODO п.55; додаток до TODO п.4). Код — `src/gitignore-editor/`, `src/bring-to-front.ts`; тести — `tests/gitignore-editor/`, `tests/bring-to-front.test.ts`.

## 1. Навіщо

Obsidian приховує файли й теки, чия назва починається з крапки, тож кореневий `.gitignore` не відкрити звичайною вкладкою (немає TFile). Раніше редактор був нерухомим модальним вікном з textarea — на desktop незручним. Тепер — за зразком переглядача лога (LOG-VIEWER.md §2.16).

## 2. Рішення власника (2026-10-08)

| # | Рішення |
|---|---|
| 2.1 | **Де.** Лише з Settings → `.gitignore` → «Edit the root .gitignore» → **[Open]**. Desktop — ОКРЕМЕ вікно ОС (pop-out) над Settings; телефон — модальне вікно НА ВЕСЬ ЕКРАН над Settings. Один компонент `GitignoreEditorPanel` для обох оболонок. |
| 2.2 | **Попередження — ЩОРАЗУ перед відкриттям**, лаконічне (має вміститися на малому екрані з великим шрифтом). Заголовок «Edit .gitignore?»; текст: «[.gitignore rules](https://git-scm.com/docs/gitignore#_pattern_format) decide which files go to GitHub. A wrong line can upload your secrets or stop needed files from syncing.»; кнопки **[Cancel]** і **[I know .gitignore rules]** (червона). Посилання — офіційна документація git, розділ PATTERN FORMAT (на GitHub правила майже не пояснено). Просте підтвердження, БЕЗ введення слова (не як Reset). |
| 2.3 | **Вже відкритий редактор** — [Open] лише виводить його наперед, без попередження (редагування вже почалось). «Наперед» по-справжньому: окреме вікно піднімається (і розгортається) через `electronWindow`, вкладка в головному вікні — Settings спершу закриваються (`bring-to-front.ts`, спільне з переглядачем лога). |
| 2.4 | **Редактор — простий textarea** (рідне Undo, надійно на телефоні, нічого не треба переносити між вікнами). Рядки не переносяться. Підказка про маркери DO-NOT-EDIT лишається одним рядком. |
| 2.5 | **[Cancel]** (і закриття вкладки/вікна/модального) — мовчки відкидає всі зміни. |
| 2.6 | **[Save]:** без змін — нічого не пише (інакше Sync побачив би зміну, якої не було) і закриває; файл ЗМІНИВСЯ на диску після відкриття (Sync приніс версію з іншого пристрою) — НЕ пише, показує «.gitignore changed on disk while you were editing. Copy your text, Cancel, and open it again.», редактор лишається з текстом; інакше — атомарний запис (`atomicWriteFile`), потім `invariants.enforce()` (відновлює керовані блоки й скидає кеш правил), «Root .gitignore saved.», закриття. Помилка запису — показується, [Save] знову доступна. |
| 2.7 | **[History]** — у Settings у тому ж рядку, поруч з [Open]: звичайний список History для `.gitignore` (та сама дія, що пункт контекстного меню для інших файлів), Settings закриваються, щоб не затулити його. |
| 2.8 | **Природне обмеження:** History для інших dot-файлів і файлів у dot-теках недоступна (Obsidian їх не показує, контекстного меню нема). Хто з ними працює — може бачити їхню історію у вебінтерфейсі GitHub. |
| 2.9 | **Відкладено (TODO п.4):** підказка всередині редактора про рядок `/.gitignore` (робить файл лише для цього пристрою). Редагування через diff2-редактор — відкинуто. |

## 3. Відкрите (знайдено під час реалізації)

- Редактор версії з History може записати `.gitignore` напряму (як будь-який файл), оминаючи попередження й `enforce()`. Керовані блоки відновить найближчий прохід commit/drain. Чи це прийнятно — вирішує власник.
