**✅ Mobile toolbar-shutter position survives a tab switch (2026-07-13, branch `diff2`, device-verified).** The last remaining mobile issue: after scrolling the collapsible toolbar "shutter" partway down, switching to another in-Obsidian tab and back reset it to the top (desktop has no shutter, so it's mobile-only; app-switch and Sync did NOT reset it — only a tab switch). Device-traced via `mobile-header-clamp.ts`'s existing log plus a temporary `INSTALL`/`DISPOSE`/`seq` + `scroll→0` instrumentation: the `seq` stayed constant (NOT a re-mount — same conceptual family as the marker-panel tab-revert but a different mechanism), and the trace pinned it exactly — on tab re-show Obsidian collapses the view (798→0→798) and zeroes `root.scrollTop`, which fires a `scroll` event; `onScroll` then did `lastUserScrollTop = root.scrollTop` and **clobbered** the saved position (`scroll→0 {was:138}`) a beat before the re-show relayout could restore it. Fix: `lastUserScrollTop` is the *user's* intended position, so only a REAL gesture may write it — track an active touch (`touchstart`→on, `touchend`/`cancel`→off with a ~400 ms momentum tail; safe because the shutter range is only ~200 px) and gate the save on it. Belt-and-suspenders for the relayout↔zero ordering race (advisor-flagged): the same involuntary drop, detected in `onScroll` while the layout is valid (`cap>0 && scrollTop < lastUserScrollTop`), is **restored right there** rather than trusting a later relayout — so it holds even if a focus cycle were relayout-then-zero. Device log confirmed across two cycles: `lastUserScrollTop` survives the `view:0` collapse, and on return the position is re-applied (138 and 115 px both held); no clobber, `seq` unchanged. The temp instrumentation was removed; the permanent `#3` relayout log stays. **Follow-up (same mechanism, second reported glitch):** in touch-only mode, clicking the toolbar's [next conflict] up to the LAST conflict collapsed the shutter fully. Traced: `scrollToConflict` calls `view.focus()`, and for the last conflict the caret is below the outer fold → a native focus-scroll (Android ignores `preventScroll`) drags the outer root up to `cap`, collapsing the toolbar (touch-only only — edit-mode is already focused so `focus()` is a no-op). Two changes generalize the shutter invariant to "the outer scroll changes ONLY by a real scroll gesture, in EITHER direction": the involuntary-restore now fires on any non-gesture move away from `lastUserScrollTop` (`!==`, not just the down-to-0 `<`); and the gesture is a touch-**move**, not touch-**start** — a TAP on a toolbar button is a touch on `root` but not a scroll, and opening the gesture window on touchstart mis-saved the focus-scroll as the user's position (device-traced: tap [next]→last set `lastUserScrollTop` 9.7→199.7). Device-confirmed: `scroll-restore {from:200,to:72/1/139}` catches the up-scroll, the shutter holds, and tab-switch/drag are unaffected.

**✅ TODO §29 — mobile paste of a copied diff-group reconstitutes instead of inserting raw text (2026-07-13, branch `diff2`, device-verified).** On Android, copying a diff-group and pasting it back dropped the RAW fenced `` ```github-easy-sync `` text into the document instead of rebuilding the group (screenshot-mobile-10).
